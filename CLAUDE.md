# CLAUDE.md — Crown Masters Adventures website

Context for Claude Code sessions working in this repo.

## The project
Rebuild of crownmastersadventures.co.ke, a Nairobi (Parklands) corporate team building company. Built by InzuHub for the client. Goals: rank on Google, get cited by AI assistants (AEO), and turn visitors into quote requests.

Read `docs/BLUEPRINT.md` first: it records the audit of the old site, the comparison with the client's own blueprint (`docs/client-brief/`), and every design decision.

## How the code works
- `data.py` holds ALL content data: business NAP, regions (slug, name, travel time, trip type, setting, intro, venues). Venue names ending in `?` are unconfirmed and render with a "name to confirm" tag.
- `build.py` generates every page into `site/`. No dependencies beyond Python 3. Inline CSS and small vanilla JS per page; no framework.
- `python3 build.py` = demo build (relative links ending in index.html, works from file://). `python3 build.py --production` = clean URLs; that output is what is committed in `site/`. Always rebuild with `--production` before committing.
- Recommended next step (per the blueprint): port to Astro on Cloudflare Pages with a headless CMS for venues and guides, keeping the same URLs, schema and copy.

## Rules that must not be broken
1. **Never invent facts.** No made-up testimonials, client names, event counts, ratings, prices, capacities or opening hours. Unknowns stay as clearly marked placeholders (`confirm()` notes, `.tbc` tags, `photo()` slots) until the client supplies them.
2. **Keep legacy URLs**: `/`, `/venues/`, `/corporate-fitness/`, `/contact-us/`, `/blog/`. New sections: `/team-building/`, `/about-us/`. Redirects live in `site/_redirects` (generated by `build.py`).
3. **Unconfirmed services** (virtual/hybrid sessions, overland trucks, SGR coordination, wellness days, ergonomics, 1,000+ person events) stay flagged until the client confirms them.
4. Every core page opens with a one-paragraph direct answer (who, what, where) and FAQ content must match its FAQPage schema word for word.
5. Titles under 65 characters, descriptions 70–165, one H1 per page, valid JSON-LD, no horizontal scroll at 390 px.
6. No video hero, no exit-intent popups, no superlatives like "Kenya's premier".

## Checks to run after changes
- Build both modes without errors.
- Parse every `application/ld+json` block; check title/description lengths and that all internal links resolve.
- Mobile overflow check at 390 px and a JS error check (Playwright with system Chrome works).
